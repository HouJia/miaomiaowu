## 1. 你是谁、维护什么

本仓库是 **iluobei/miaomiaowu 的 HouJia fork**，在 upstream 功能之上增加：

- **子路径** `/mmw/`（`extensions/basepath` + `forkserver`）
- 多用户、多订阅文件、探针流量
- **规则类别**（源自 sublink 的 GeoSite 分类勾选）
- 可选 **ACL4SSR / Aethersailor ini URL** 模板模式

分支模型见 [`技术方案-分支与上游同步.md`](技术方案-分支与上游同步.md)。

## 2. 日常开发流程

```bash
git checkout hjs-feature
git pull origin hjs-feature
# … 改代码 …
./scripts/build-fork.sh          # 本地冒烟
git commit -m "feat(scope): 摘要"
git push origin hjs-feature
# 验证通过后
git checkout hjsmaster && git merge hjs-feature && git push origin hjsmaster
```

**禁止**：在 `hjsmaster` 上直接开发；在 `upstream/main` 上提交 HouJia 定制。

## 3. 构建与镜像

| 方式 | 命令 | 产出 |
|---|---|---|
| 本地二进制 | `./scripts/build-fork.sh` | `build/fork/forkserver` + 前端 `internal/web/dist` |
| Docker（NAS） | `docker build -f fork/docker/Dockerfile.fork -t miaomiaowu-fork:hjsmaster .` | 含 `/mmw/` 健康检查 |

环境变量（`.env.example`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `BASE_PATH` | `/mmw` | 后端 StripPrefix |
| `VITE_BASE_PATH` | `/mmw/` | 前端资源与路由 |
| `PUBLIC_ORIGIN` | 空 | 订阅外链固定公网域名时用 |

## 4. QNAP 运维

| 项 | 值 |
|---|---|
| 容器名 | `miaomiaowu` |
| 端口 | `8080` |
| 数据卷 | `/share/Container/miaomiaowu/data`、`subscribes`、`rule_templates` |
| 构建缓存目录 | `/share/Container/miaomiaowu-build` |
| 公网 | `https://houjia.mycloudnas.com:44/mmw/` |

升级步骤：

1. rsync 或 `git pull` 同步 `hjsmaster` 到 `miaomiaowu-build`。
2. `docker build -f fork/docker/Dockerfile.fork -t miaomiaowu-fork:hjsmaster .`
3. `docker stop miaomiaowu && docker rm miaomiaowu`，用**相同卷与环境变量** `docker run`。
4. `curl -sI http://127.0.0.1:8080/mmw/` → 200。

## 5. 分流规则怎么维护

妙妙屋有 **三条规则路径**，不要混用概念：

| 模式 | 适用 | 如何维护 |
|---|---|---|
| **规则类别（custom）** | A/B/C 按需勾选 Google、AI、社交等 | 生成器 / 订阅文件编辑；底层 `RULE_CATEGORIES`（与 sublink 同源） |
| **远程 ini 模板** | 已有 ACL4SSR / Aethersailor ini | 生成器选「模板模式」，填 `rule_source` URL 或 `template-presets` |
| **V3 模板** | 复杂 proxy-groups + rule-providers | `rule_templates/*.yaml` 或管理后台 V3 模板 |

**已有成熟 `config-template.ini`（subconverter）时**：

- **不能**把 ini 原样「导入」到类别模式；subconverter 的 `custom_proxy_group` / `ruleset=` 与妙妙屋内置生成器不是同一套运行时。
- **推荐**：
  1. **继续用 subconverter**：sub-web → `/subapi?config=houjia-template.ini`，机场 URL 走现有链（Verge / OpenClash 填转换后订阅）。
  2. **妙妙屋内复刻策略**：把 ini 里的**策略组命名与规则意图**迁到 V3 模板或类别 + 自定义规则；或模板模式指向 **同一 ini 的 HTTPS raw URL**（妙妙屋拉 ini 作 rule_source，仍经自有 Clash 构建管线，非 subconverter 进程）。
  3. **分工**：节点与用户分发用妙妙屋；全量 houjia 规则用 subapi；轻量场景用妙妙屋类别勾选。

## 6. 与 sub-web / subapi 的边界

```text
机场订阅 URL
    ├─→ /subapi/sub?target=clash&config=houjia-template.ini   （subconverter，完整 INI）
    ├─→ /mmw/… 短链 / 用户订阅                                 （妙妙屋，节点+自选规则）
    └─→ /sublink/…                                              （Sublink，轻量类别+短链）
```

三者**都不是**「只导出 ini」；ini 是 subconverter **输入**；妙妙屋/Sublink 输出 **Clash YAML**（内置 rule-providers）。

## 7. 故障速查

| 现象 | 检查 |
|---|---|
| `/mmw/` 404 | 容器 `BASE_PATH`、NPM `X-Forwarded-Prefix`、是否用 fork 镜像 |
| API 打到 `/api` 而非 `/mmw/api` | 前端是否 fork 构建（`vite.config.fork.mts`） |
| 订阅短链缺 `/mmw` | `PUBLIC_ORIGIN`、basepath 中间件 |
| 合并上游后启动失败 | `internal/app/run.go` 是否合入上游路由；`main.go` 是否仍为薄入口 |

更多子路径细节：`docs/iteration/basepath-extension.md`。
