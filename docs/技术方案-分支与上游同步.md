> **配套**：与 `sub-web` `/subw/`、`SubConverter-Extended` `/subapi/` 并列，**不替代** subconverter 转换链

## 1. 目标

- 与 `sub-web`、`SubConverter-Extended` 等 HouJia fork **同一套分支语义**（`hjs-feature` 开发、`hjsmaster` 交付）。
- 保留 fork 专有能力：**子路径 `/mmw/`**、多用户订阅、规则类别勾选、探针流量等。
- 按需合并上游 `iluobei/miaomiaowu` 发版（如 `v0.8.x`），冲突面控制在 `internal/app`、`extensions/`、`fork/`。

## 2. 分支职责

| 分支 | 职责 |
|---|---|
| **`hjsmaster`** | **交付主线**：QNAP 镜像、NPM `/mmw/` 反代、生产数据卷 |
| **`hjs-feature`** | **唯一开发分支**：子路径扩展、HouJia 定制、合并上游前的集成验证 |
| **`upstream/main`**（远程跟踪） | 上游 `iluobei/miaomiaowu` 的 `main`，只 fetch，不直接部署 |
| `main`（可选） | 可保留为上游镜像只读参考；**禁止**在其上堆 HouJia 定制 |

约定：

- GitHub 默认分支建议设为 **`hjsmaster`**。
- 不在 `upstream/main` 上直接做 NAS 定制提交。

## 3. 远程与跟踪关系

```bash
git remote -v
# origin    git@github.com:HouJia/miaomiaowu.git      # 我们的 GitHub
# upstream  git@github.com:iluobei/miaomiaowu.git    # 上游只读
```

| Remote | 用途 |
|---|---|
| `origin` | 推送 `hjs-feature`、`hjsmaster` |
| `upstream` | fetch 上游 tag / main，合并进 `hjs-feature` |

## 4. Fork 与上游差异（合并时必须保留）

| 区域 | HouJia 保留项 |
|---|---|
| `extensions/basepath/` | `BASE_PATH` 默认 `/mmw`、StripPrefix、订阅 URL 重写 |
| `fork/` | `Dockerfile.fork`、`docker-compose.fork.yml`、`nginx-subpath.example.conf` |
| `fork/cmd/forkserver` | 组合 `extensions/basepath` + `internal/app` |
| `.env.example` | `BASE_PATH=/mmw`、`VITE_BASE_PATH=/mmw/` |
| `cmd/server/main.go` | 极薄 `app.Run()`（勿恢复上游巨型 `main`） |
| `docs/iteration/basepath-extension.md` | 子路径设计说明 |

合并上游后必做：

1. 确认 `internal/app/run.go` 已吸收上游 `cmd/server/main.go` 的新路由/中间件（DNS 补丁、限速、测速等）。
2. `cmd/server/main.go` **保持**薄入口。
3. `./scripts/build-fork.sh` 或 `fork/docker/Dockerfile.fork` 构建通过。

## 5. 同步上游 iluobei

```bash
git fetch upstream --tags
git checkout hjs-feature
git merge upstream/main -m "merge: upstream vX.Y.Z into hjs-feature"
# 冲突优先：保留 extensions/、fork/、cmd/server/main.go 薄入口；run.go 手工合入上游启动逻辑
./scripts/build-fork.sh
git push origin hjs-feature
```

交付：

```bash
git checkout hjsmaster
git merge hjs-feature -m "merge: hjs-feature <摘要>"
git push origin hjsmaster
```

## 6. NAS / NPM 部署

```bash
# 本机或 NAS 构建目录同步后
cd fork/docker
docker build -f Dockerfile.fork -t miaomiaowu-fork:hjsmaster ../..
docker run -d --name miaomiaowu --restart unless-stopped \
  -p 8080:8080 \
  -e BASE_PATH=/mmw \
  -e VITE_BASE_PATH=/mmw/ \
  -v /share/Container/miaomiaowu/data:/app/data \
  -v /share/Container/miaomiaowu/subscribes:/app/subscribes \
  -v /share/Container/miaomiaowu/rule_templates:/app/rule_templates \
  miaomiaowu-fork:hjsmaster
```

NPM（`houjia.mycloudnas.com`）：

```nginx
location = /mmw { return 301 $scheme://$http_host/mmw/; }
location ^~ /mmw/ {
    proxy_set_header X-Forwarded-Prefix /mmw;
    proxy_pass http://192.168.0.6:8080;
}
```

验收：`curl -sI https://<域名>/mmw/` → 200；登录后订阅短链含 `/mmw/` 前缀。

## 7. 与 subconverter / sub-web 的关系

| 组件 | 路径 | 作用 |
|---|---|---|
| SubConverter-Extended | `/subapi/` | INI 模板 + 机场订阅 → Clash YAML |
| sub-web | `/subw/` | 转换参数 UI，调用 `/subapi` |
| **妙妙屋** | `/mmw/` | 节点池、用户、多订阅文件、规则类别、短链 |

妙妙屋**内置** sublink 式规则类别与 Clash 生成，**不依赖** subconverter 进程；可选用远程 ACL4SSR **ini URL** 作模板源（生成器「模板模式」），与 NAS 上 `houjia-template.ini` 是**并行方案**，见 `docs/维护指南.md`。

## 8. 迭代流程

1. 在 `hjs-feature` 开发 → 本地或 NAS `build-fork` 验证。
2. `push origin hjs-feature`。
3. 合并 `hjsmaster` → NAS 重建镜像 → 滚动容器。
4. 上游发版：§5 合并 → 重复 1～3。

**维护**：变更分支或 NPM 约定时，同步更新本文、`docs/维护指南.md`、`README.md` 中 fork 小节。
